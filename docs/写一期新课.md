# 从零写一期新课

这份操作指南面向课程维护者。准备好文字与图片即可，不需要修改任何 `.py` 文件。第一次使用先按 README 安装 Python 依赖。

## 1. 创建课程骨架

在仓库根目录运行：

```bash
python run.py --new 城市战
```

会得到：

```text
courses/城市战/
├── course.txt
├── deck.txt
├── notes/01.txt … 05.txt
└── 素材/说明.txt
```

已有同名目录会报错，不会覆盖。课程名是单层目录名，不能用 `../` 或绝对路径。请保留目录层次，尤其不要把图片挪到 `deck.txt` 旁边。

## 2. 先确定课程目标和时长

编辑 `course.txt`。下方代码块中字段与值之间应为**实际制表符**。编辑器中可以开启「显示空白字符」核对，不能用几个空格替代。

```text
title	城市空间与信息判断
subtitle	一堂以证据为中心的讨论课
org	军事社 · 专题课程
docid	CITY-01
deckname	CITY / INFORMATION
time_target_min	25
time_target_max	30
theme	military_light
```

`title` 决定成品名称；`org` 是机构名；两项时长用分钟。其余项可省略，默认值见[内容格式](内容格式.md)。

## 3. 规划每页一个观点

建议 25–30 分钟的课先规划约 15–20 页，再根据内容调整。推荐顺序：开场问题、概念与背景、主要讨论、总结、提问、参考来源。

- 每页一个核心观点，通常 3–5 个关键点，避免满屏项目符号。
- 图片应解释问题或提供证据，不要仅为填满空白。
- 最后一页使用 `sources` 列出本课实际使用的来源。
- 严肃题材保持克制，不娱乐化或美化战争。
- 不伪造战例、人物、数据与引语。来源冲突时说明差异或给出有依据的区间；无法核实的话不要包装为「某人说过」。

## 4. 填写逐页内容

`deck.txt` 用 `[01]`、`[02]` 等分隔页面，必须从 01 连续编号，最多 99 页（还受主题页数上限约束）。每页必填 `layout` 与 `title`。

封面例子：

```text
[01]
layout	cover
title	城市空间
subtitle	从有限信息到有边界的结论
question	只看一张照片，哪些问题无法回答？
key	先区分观察、解释与未知。
image	封面.png
caption	概念示意，非真实地点；填写作者、来源和授权。
footer	资料来源：填写本课真实使用的文献。
time	120
```

普通内容页例子：

```text
[02]
layout	points
title	先把信息分成三类
key	不要把推断写成已经证实的事实。
bullet	观察：材料中可以直接确认的内容。
bullet	推断：根据证据形成、仍需说明依据的解释。
bullet	未知：现有材料没有回答的问题。
image	信息分类.png
caption	作者原创示意。
footer	资料来源：填写真实出处。
time	90
```

可选侧图不填写时，文字会使用全部内容宽度。字段不能随意混搭；例如分栏用 `column`，表格用 `row`。全部用法见[布局参考](布局参考.md)。

把所有 `time` 相加，确认落在目标区间内。省略 `time` 时默认 90 秒；正式课程建议每页明确填写。模板的五页只是格式骨架，应按实际内容扩展，不建议直接用五页占位内容讲满 25 分钟。

## 5. 放入图片

图片放入 `素材/`；文本只写相对文件名，支持子目录。图片不能引用到素材目录外。

- 封面必须一张全出血图片，至少 **2.07 MP**，建议 **4.5 MP** 以上；1920×1080 是合格下限。
- 侧图建议至少 **0.8 MP**；低于此值会警告。
- 照片尽量写明时间、地点、原始来源和授权；概念图明确标成示意。
- 支持 Pillow 可解码且能转换为 RGB 的栅格图片，推荐 PNG/JPEG；SVG 请先导出 PNG。

封面会按 16:9 居中裁切，并将压暗效果直接合成进图片像素。重要人物或标注请远离裁切边缘。其他布局保持图片比例，不拉伸也不随意裁切。

## 6. 写逐页讲稿

每页对应一个 `notes/NN.txt`，例如 `notes/02.txt`。缺文件或只有空白会失败。

```text
【本页讲解重点】
这里写完整讲稿。可以分段，也可以包含中文引号“例子”。
〔停顿，邀请同学回答。〕
```

文本原样进入 PPT 演讲者备注与 Word；Word 中 `【…】` 开头的行加粗，`〔…〕` 开头的行用主题强调色（默认红色）。空行也会保留。

Word 按每张幻灯片生成一页 A4：上半部分是从 PPT 反读的正文，后面是讲稿。正文与讲稿过长时先调整字号，仍无法容纳会要求精简或拆页；不要通过删讲稿绕过校验。

## 7. 构建并处理检查结果

```bash
python run.py 城市战
```

产物写入本课 `输出/`。通过后得到 `<标题>.pptx` 与 `<标题> 讲稿.docx`。标题含 Windows 禁止字符时替换为下划线，超过 70 字符时截短。

常见修复方法：

| 提示 | 处理 |
|---|---|
| 未识别的 key | 按报错页码、字段名和行号修正拼写 |
| V2 时长不符 | 调整逐页 time 或课程目标，不改校验规则 |
| V3 缺少讲稿 | 补齐对应 `notes/NN.txt`，写入非空讲稿 |
| V8 素材不存在 | 核对文件名、大小写与报错给出的完整期望路径 |
| V5 封面像素不足 | 换高分辨率原图；引擎放大像素不会使原图过关 |
| V9 放不下 | 精简文字、拆页，或选择更合适的布局 |
| T4 要点过多 | 尽量拆成每页 3–5 个要点 |

修改内容后重新构建；`--check` 只检查已有成品，不负责更新文件。

## 8. 交付前复核

打开 PPT，确认字体与素材；打开 Word，检查讲稿与分页。需要渲染时使用现成 LibreOffice 转 PDF，再由 Poppler 导出预览，不能自建 PPT 渲染器。

中文文件名由 Python 处理；调用系统原生命令时建议用 Python 将成品复制到临时目录，改为 `slides.pptx`、`notes.docx` 后再转换，参考 `tests/acceptance.py` 的 `render_artifacts`。这样避开 Windows 原生工具的中文参数编码问题。

渲染 PNG 的边缘若与预期不一致，先检查 V4 几何结果与 PDF 页面尺寸，不要仅凭缩略图边缘判定越界。

## 9. 换主题（可选维护）

这一操作需要少量 Python 配置，新增课程本身不需要。复制主题字典：

```python
THEMES["navy_light"] = deepcopy(THEMES["military_light"])
THEMES["navy_light"]["palette"].update(paper="EEF3FF", accent="244B80")
```

然后只在本课 `course.txt` 中将 `theme` 改为 `navy_light`。布局函数保持不变。字体、字号、边距、页数上限也集中在主题配置中。
