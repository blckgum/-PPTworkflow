# 课程 PPT 生成工作流 — 需求规格书

> **这份文档的用途**：给负责实现的 AI（或人）看的完整需求。
> 目标是做出一个**可复用的课件生产工作流**，而不是某一个具体课件。
> 请先读完「已确认的决定」再动手，不要重新提问已经被决定的事情。

---

## 0. 一句话目标

做一个仓库：**以后每开一期新课，只需要新建一个纯文本内容文件和一个素材文件夹，运行一条命令，就得到成品 PPT + Word 讲稿，并且自动通过质量校验。加新课程不需要改代码。**

---

## 1. 背景

用户是高中军事社团负责人，要持续开设一系列 25–30 分钟的专题讲座，每期主题不同（例：
《Human Factors：真实战场中的压力、风险与决策》《CQB：标准动作、复杂环境与临场判断》）。

目前每一期都是**手写一个 Python 渲染脚本**，页面布局、页数、章节都写死在代码里。
换主题就要重写代码，无法持续维护。

**核心痛点**：内容与代码耦合。要的是**内容与引擎分离**。

---

## 2. 已确认的决定（不要重新询问）

| 编号 | 项目 | 决定 |
|---|---|---|
| D1 | 流程范围 | **PPT + Word 讲稿 + 自动校验，全流程** |
| D2 | 内容格式 | **纯文本 `key<TAB>value`**，不用 YAML/JSON/Markdown |
| D3 | 主题 | **主题可切换**：抽象成主题配置，内置一套「白色军事简报」主题 |
| D4 | 旧课件兼容 | **不要求 1:1 复现旧版**，可以重新设计得更通用 |
| D5 | 维护者能力 | 用户**可以**改少量 Python 配置（主题色、页数上限等），但**不想为了加一期新课而写渲染逻辑** |
| D6 | 语言 | 内容、文档、注释都用**中文**；代码标识符用英文 |

---

## 3. 非目标（明确不做）

- ❌ 不做图形界面 / 网页编辑器
- ❌ 不追求任意版式的自由排版（只提供一组**够用的布局类型**）
- ❌ 不生成图片素材里的人物/场景（素材由用户提供）
- ❌ 不支持动画、切换效果、音视频
- ❌ 不自动做内容创作（引擎只负责排版，内容由人/AI 写进文本文件）

---

## 4. 交付物

1. **完整可运行仓库**（clone 后 `pip install -r requirements.txt` 即可跑）
2. **引擎代码**：内容解析 + 布局渲染 + PPT 生成 + Word 生成 + 校验
3. **一套内置主题**：白色军事简报
4. **一个完整示例课程**（≥15 页，含讲稿、含图片，能一键构建并通过校验）
5. **中文文档**：
   - `README.md`：这是什么、怎么装、怎么跑
   - `docs/写一期新课.md`：**从零加一期新课的完整步骤**（这是最重要的文档）
   - `docs/内容格式.md`：字段与布局的完整参考
6. **一份空白模板课程**：`courses/_template/`，复制改名就能开新一期

│   ├── layouts.py              # 布局函数 + 注册表
│   ├── build_pptx.py
│   ├── build_docx.py

**关键约定**
- `courses/<课程>/` 下只有内容，没有代码。
- 引擎不认识任何具体课程名。
- 新增一期 = 复制 `_template/` → 改名 → 填内容。

## 6. 内容格式规范（本项目的核心）

### 6.1 `course.txt`（每门课一个）

```
title	CQB：标准动作、复杂环境与临场判断
subtitle	—— 以 2004 年第二次费卢杰战役为案例
org	军事社 · 课程
docid	CQB-01
deckname	CQB / FALLUJAH 2004
time_target_min	25
time_target_max	30
theme	military_light
```

必需字段：`title`、`org`、`time_target_min`、`time_target_max`。
其余可选，有默认值。

### 6.2 `deck.txt`（幻灯片内容）

以 `[NN]` 分页，`NN` 为页序号（两位数，从 01 起）。每页内每行一个 `key<TAB>value`。

```
[01]
layout	cover
image	研究街道地图的usnavy士兵 可做背景.jpg
title	CQB
subtitle	标准动作、复杂环境与临场判断
subtitle2	—— 以 2004 年第二次费卢杰战役为案例
question	如果战场从开阔地变成一栋陌生建筑，究竟发生了什么变化？
key	CQB 不是简单地把战斗搬进房间，而是把人的认知、空间和时间压力同时推高。
caption	2004 年 11 月，费卢杰。图片来源：美国海军官方照片档案（公有领域）。
time	120

[02]
layout	points
title	CQB 是什么
subtitle	CLOSE QUARTERS BATTLE · 近距离战斗
key	在极近距离、空间高度受限、信息被建筑切割的条件下进行的战斗。
bullet	开阔环境：信息相对连续。
bullet	城市 / 建筑环境：信息被空间切割。
bullet	CQB：必须在有限信息下快速判断。
image	图A.png
caption	示意图，不代表任何具体建筑。
footer	资料来源：……
time	90
```

**字段类型**

| 字段 | 含义 | 可重复 |
|---|---|---|
| `layout` | 布局类型（必填，见第 7 节） | ❌ |
| `title` / `subtitle` | 标题 / 副标题 | ❌ |
| `key` | 本页核心句（高亮框） | ❌ |
| `bullet` | 要点，一行一条 | ✅ |
| `body` | 段落文字（比 bullet 长） | ✅ |
| `head` + `body` | 成对出现时渲染为小标题+正文块 | ✅ |
| `kv` | 键值对，格式 `名称=内容` | ✅ |
| `row` | 表格行，列用 `|` 分隔；第一行为表头 | ✅ |
| `card` | 卡片，格式 `标题|正文` | ✅ |
| `step` | 流程步骤（顺序） | ✅ |
| `num` | 编号条目，格式 `编号 文本` 或自动编号 | ✅ |
| `image` / `image2` | 素材文件名（相对 `素材/`） | ✅ |
| `caption` / `caption2` | 对应图片说明 | ✅ |
| `footer` | 页脚来源注释 | ❌ |
| `time` | 本页建议讲解秒数 | ❌ |
| `note` | 主讲人提示（渲染在页面上） | ❌ |

**规则**
- 制表符分隔，不用空格（允许连续空格出现在值内）。
- `#` 开头的行是注释，忽略。
- 未识别的 key → **报错并指出页码和 key 名**，不要静默忽略（否则打错字会丢内容）。
- 引用的图片文件不存在 → **报错并列出期望路径**。

### 6.3 `notes/NN.txt`（讲稿）

每页一个文件，纯文本，原样进入 PPT 的演讲者备注栏，并原文进入 Word 讲稿。

约定：
- `【…】` 开头的行渲染为加粗小标题
- `〔…〕` 开头的行渲染为红色提示
- 其余为正文

### 6.4 内容与代码的硬边界

**引擎的 Python 文件里不得出现中文正文。** 中文只允许出现在：
- `courses/` 下的一切文件
- `deckflow/strings.py`（引擎自绘标签，用 `\uXXXX` 转义写）
- 注释与文档

原因见第 11 节第 1 条，这是本项目最容易翻车的地方。

## 7. 内置布局（必须实现的清单）

每个布局是一个函数：输入（本页字段字典 + 主题 + 页码 + 总页数），在幻灯片上画出对应版式。

| layout | 用途 | 关键字段 |
|---|---|---|
| `cover` | 封面，全出血大图 + 大标题 + 开场问题 | image, title, subtitle, question, key |
| `statement` | 单句大字，视觉留白 | title, subtitle |
| `points` | 标题 + 核心句 + 若干要点，可带侧图 | title, key, bullet[], image |
| `blocks` | 标题 + 多组 head/body | head+body 对 |
| `columns` | 2–3 栏对照 | column（`标题|正文`，2–3 条） |
| `table` | 表格 | row[] |
| `kv` | 键值清单 + 侧图 | kv[], image |
| `chain` | 竖向编号流程 | step[] |
| `flow` | 横向流程（带箭头） | step[] |
| `diagram` | 整幅示意图 + 说明面板 | image, caption, key, body |
| `grid` | 2×N 卡片 | card[] |
| `dark` | 深色页，用于强观点 | title, statement, reason[], key |
| `summary` | 编号总结 | num[] |
| `closing` | 结尾两行大字 | title, title2, subtitle |
| `sources` | 参考来源列表 | source[] |
| `qa` | 提问页 | title, key, body |
| `section` | 章节分隔页（可选） | title, subtitle |

**要求**
- 布局必须**自动处理文字换行与高度**，不能溢出页面（见校验 V9）。
- 有 `image` 时自动放置侧边图并配 `caption`；没有就不留空。
- 页眉（机构名、文档号、页码）与页脚（来源、建议时长）由引擎统一绘制，布局函数不管。
- 图注、来源、时长格式全引擎统一。

## 8. 主题系统

`deckflow/theme.py` 定义一套主题，至少包含：

```python
PALETTE = {
    'paper': ..., 'paper_alt': ..., 'ink': ..., 'ink_soft': ...,
    'accent': ..., 'accent_mid': ..., 'emphasis': ...,
    'dark_bg': ..., 'white': ..., 'offwhite': ...,
}
FONTS = {'cjk': '微软雅黑', 'head': 'Bahnschrift', 'mono': 'Consolas'}
GEOMETRY = {'slide_w': 13.333, 'slide_h': 7.5, 'margin': 0.62, ...}
TYPE_SCALE = {'h1': 25, 'h2': 15, 'body': 11.5, ...}
```

- 内置主题：`military_light`（米白纸底 + 橄榄绿结构 + 红色强调 + 细横线，上方元数据条）。
- `course.txt` 里 `theme` 字段指定用哪套。
- 加新主题 = 在 `theme.py` 加一个字典，不改布局代码。

## 10. 自动校验（必须实现，构建后自动跑）

| 编号 | 检查 | 判据 |
|---|---|---|
| V1 | 页数 | PPT 页数 == `deck.txt` 中 `[NN]` 块数 |
| V2 | 时长 | `Σtime` 落在 `time_target_min..max` 区间，否则报错并给出实际值 |
| V3 | 备注 | 每一页都有非空演讲者备注 |
| V4 | 越界 | 所有形状不超出幻灯片边界（容差 0.01 in） |
| V5 | 开场图 | 第 1 页存在覆盖整页的图片，且像素 ≥ 2.07 MP（1920×1080） |
| V6 | 讲稿完整性 | Word 讲稿包含每一页的正文与讲稿，页数与 PPT 一致 |
| V7 | 源码卫生 | 引擎 `.py` 文件中不存在「中文文本里夹 ASCII 双引号」——见第 11 节第 1 条。用词法/正则检查，报错指出文件行号 |
| V8 | 素材引用 | `deck.txt` 引用的每个图片文件都存在于 `素材/`，缺失即报错 |
| V9 | 文字溢出 | 估算每页文字块所需高度，超出其框架一行以上则报警（允许警告而非失败） |
| V10 | 禁用词 | 可选：检测「XX 说过」类无法核实的引语格式，提示人工确认 |

校验结果用清晰的中文表格打印：
```
[通过] 页数 19 页
[通过] 总时长 26m15s（要求 25–30 分钟）
[失败] 第 12 页缺少讲稿：notes/12.txt 不存在
```

## 11. 技术约束与已知陷阱（**最重要的一节**）

这些都是实际踩过的坑，请直接采纳，不要重新试错。

### 11.1 Python 源码里中文夹 ASCII 双引号 → 整个模块语法错误

`"今天的问题不是"为什么打"，而是……"` 会提前终止字符串。一旦出现，Python 报的是
`invalid character '，' (U+FF0C)`，错误行号还可能指在别处，极难定位。

**曾经的真实事故**：为修这个问题连续写了几轮「自动修复脚本」，每次都把文件改得更坏
（把 U+201C 塞进字符串定界符、误删函数调用）。最终解法不是修，而是**重写**。

**要求**
- 中文正文一律放在 `courses/` 的文本文件里，引擎代码不写中文正文。
- 必须写中文时用 `\uXXXX` 转义，或统一用全角引号 「」/“”。
- 加一条 lint（V7）防止回归。

### 11.2 python-pptx 中 textbox 与 autoshape 不能靠名字区分

`add_textbox` 生成的形状名在**每一页都重复**（`TextBox 1`、`TextBox 2`…）。
要区分应判断 XML 结构：autoshape 有 `<p:cNvSpPr>`，textbox 没有。

### 11.3 `spPr.find("a:xfrm")` 会命中嵌套节点

`find` 会搜索所有后代，autoshape 的 `custGeom/path` 里可能还有 `a:xfrm`。
必须取**直接子元素**。

### 11.4 OOXML 手写时的元素顺序

- `a:latin` / `a:ea` / `a:cs` 必须排在**填充元素之后**。
- 字间距 `spc` 是 `a:rPr` 的**属性**，不是子元素。
- 顺序错了 PowerPoint 可能报「无法打开文件」。

### 11.5 中文断行必须逐字符，不能按空格

PowerPoint 对 CJK 是逐字符断行。若用「按空格切词」的算法估算行数，
中文会被当成一个超长单词 → 行数严重低估 → 版面溢出。
自己写估算器时必须对 CJK 逐字符贪心换行。

### 11.6 自己写渲染器做视觉校验是错误方向

本项目曾花约 35% 的时间自建 XML→PNG 渲染器，而它本身有 4 个 bug，导致误判成品损坏。
**正解**：用系统/环境里现成的 LibreOffice 命令行渲染。

```bash
soffice --headless --convert-to pdf deck.pptx
pdftoppm -png -r 100 deck.pdf out/page
# 或直接：--convert-to png
```

**若环境提供 `libreofficeKit` 之类的封装，优先用它，不要自建渲染器。**

### 11.7 LibreOffice 渲染出的 PNG 可能有右侧/底部裁切，别当成版面溢出

实测某封装返回的 PNG 宽高比与它自己声明的页面矩形不一致
（1334×751 = 1.776 vs 1280×720 = 1.778），导致右边缘被裁。
判断「是否真的溢出」应以 V4 的几何检查为准，或看 PDF 的 `MediaBox`。

### 11.8 依赖安装与 `libs/`

- 默认要求 `pip install python-pptx python-docx Pillow`。
- 不要把 `libs/`（本地离线依赖，30 MB / 858 文件）提交进仓库。
- 若脚本里有 `sys.path.insert(0, 'libs')`，目录不存在时是**无害的空操作**，
  可保留以兼容离线环境。

### 11.9 目录结构是硬依赖

内容文件与素材文件夹的相对位置固定（`<课程>/素材/` 与引擎同级约定），
不要为了「看起来整齐」把它们拍平到同一层，脚本会找不到文件。

### 11.10 中文路径与文件名

- 中文路径**不要直接作为参数传给原生命令**（Windows 下会乱码）。
  让 Python 用 `cwd` + 相对路径，或把路径写在脚本内部。
- 单个中文文件名过长会触发 Windows 260 字符限制，git 需要
  `git config core.longpaths true`。
- zip 内部路径**永远用正斜杠**；`os.path.join` 在 Windows 产出反斜杠，匹配不到条目。

### 11.11 全出血背景图的压暗要烘进像素

用 PIL 把渐变暗角合成进图片再插入，不要用半透明色块叠加
（不同 PowerPoint 版本透明度表现不一致）。

### 11.12 图片分辨率门槛

- 全出血（铺满 1920×1080）：**≥ 2.07 MP**，建议 ≥ 4.5 MP。
- 侧边面板（约 4.5 in 宽 @180 PPI）：≥ 0.8 MP。
- 引擎应在图片过小时**警告**，而不是默默糊掉。

### 11.13 讲稿与 PPT 不能两处维护

Word 讲稿的幻灯片正文部分应**从生成的 pptx 反读**，而不是另存一份文本，
否则两边一定会不一致。

## 12. 验收测试

实现完成后，必须能通过以下场景：

**T1 从零加一门课（核心测试）**
1. `python run.py --new 测试课`
2. 得到 `courses/测试课/` 下完整骨架
3. 只编辑 `course.txt`、`deck.txt`、`notes/`、放入 2–3 张图
4. `python run.py 测试课`
5. 产出 pptx + docx，且**全部校验通过**
6. **全程没有修改任何 `.py` 文件**

**T2 校验有效性**
- 故意把 `Σtime` 改成 40 分钟 → V2 必须报错
- 故意删掉 `notes/05.txt` → V3 必须报错
- 故意在 `deck.txt` 写一个不存在的图片名 → V8 必须报错并给出路径
- 故意在引擎里写一句带 ASCII 引号的中文 → V7 必须报错

**T3 主题切换**
- 复制 `military_light` 改两处颜色 → 生成结果跟着变，布局代码不变

**T4 版面**
- 任意页面文字不溢出、不重叠、不出血
- 每页 ≤ 5 个要点（超过时警告）

## 13. 内容写作规范（引擎需支持，也写进文档）

来自用户的长期要求，应当体现在布局设计与文档中：

- 每页**一个核心观点**，最多 3–5 个关键点
- 不要满屏 bullet points
- 图片不是装饰，是叙事的一部分
- 历史照片尽量注明 **时间 / 地点 / 来源**
- 每页页脚注明资料来源
- 末尾单独一页 `sources`
- 严肃题材：克制，不娱乐化、不美化战争
- **不得伪造**战例、人物、数据、引语；来源冲突时给区间或注明差异
- 不得把无法核实的说法写成「某人说过」
